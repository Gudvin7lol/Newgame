# Библиотека строительных работ «Замер» (+155)

## Состав

Каталог содержит **245 операций** (34 базовые и 211 дополнительных) по направлениям:
подготовка, демонтаж, конструктив, черновые работы, стены, плитка, полы, потолки,
электрика, слаботочные системы, сантехника, отопление, вентиляция, двери/окна,
финишный монтаж, контроль и сдача.

Каждая операция задаёт:
- уникальный стабильный `code` (сохраняется в `WorkTask.operationCode`);
- понятное название и группу (`phase`);
- базу расчёта объёма: площадь пола/стен/потолка, длина плинтуса или количество;
- **ориентировочные**, а не нормативные человеко-часы на единицу;
- список типичных предыдущих операций (`requiredCodes`);
- флаги `optional` и `catalogOnly`.


## Новая группировка библиотеки

Для выбора на телефоне все 245 операций разложены в **11 главных разделов**.
Внутри каждого раздела доступны тематические подразделы. Например:
«Стены → Штукатурка», «Пол → Основания и стяжки»,
«Электрика → Слаботочные сети», «Инженерия → Вентиляция».

| Главный раздел | Операций |
|---|---:|
| Подготовка | 10 |
| Демонтаж | 17 |
| Конструктив | 13 |
| Стены | 34 |
| Пол | 37 |
| Потолок | 19 |
| Электрика | 34 |
| Инженерия | 39 |
| Двери и окна | 15 |
| Оборудование и финиш | 13 |
| Контроль и сдача | 14 |
| **Итого** | **245** |

Открыть библиотеку: **Работы → Добавить работу → Выбрать операцию
из библиотеки → Главный раздел → Подраздел → Операция**.
Поиск работает по названию, коду и названию раздела; для быстрого
поиска по всем работам не нужно сначала выбирать группу.

Иерархия вычисляется в `WorkOperationTaxonomy`. Она **не изменяет**
`WorkOperation.code`, прежний `phase` и уже созданные задачи.
Это важно для старых проектов, журнала, предшественников и резервных копий.

## Как пользоваться

**Работы → Добавить работу → Выбрать операцию из библиотеки.**

Поиск работает по названию и коду. Горизонтальные фильтры позволяют выбрать
направление. После выбора подставляются название, единица измерения и
ориентировочная трудоёмкость. Когда указано конкретное помещение, рассчитываются
соответствующие площади/периметр из замкнутой геометрии. Эти числа можно
отредактировать перед сохранением.

**Работы → Сформировать работы из планировки** продолжает использовать только
проверенные базовые этапы и явно отмеченные существующие дополнительные этапы.
Все 211 новых подробных позиций имеют `catalogOnly: true`, поэтому не
появляются во всех комнатах при массовой генерации.

## Производственная логика

- Не создавайте все варианты одной технологии одновременно: например, штукатурку
  цементную и гипсовую, несколько альтернативных напольных покрытий или
  натяжной и ГКЛ-потолок без отдельного проектного решения.
- Сметная площадь стены берётся **чистая**, с учётом проёмов. Площадь пола
  использует внутреннюю геометрию помещения.
- Позиции, где объём не выводится из модели (точки электрики, инженерные
  трассы, устройства, объём демонтажа), нужно замерить и подтвердить вручную.
- Предыдущие этапы учитываются внутри выбранной комнаты. Добавление операции
  не означает, что соответствующий этап физически необходим в каждом объекте.
- Человеко-часы являются начальными оценками: зависят от основания, сложности
  отделки, геометрии, оборудования, числа рабочих, технологии и норм подрядчика.
  Они не заменяют сметные нормативы и технологические карты.
- Электрические щиты, инженерные системы, проёмы в несущих элементах и другие
  ответственные работы требуют отдельного проекта, проверки и профильных
  специалистов.

## Защита данных

Базовые операции сохраняют прежние коды. Новые коды добавляются отдельно.
Существующие работы, принятые объёмы, статусы и журнал не перезаписываются.
Повторная автоматическая генерация отсеивает `generatedKey`, а не создаёт
второй комплект работ.


## Отделка по конкретным стенам, первая реализация

**Работы → Отделка по отдельным стенам → Помещение → Выбор стены на 2D-плане.**

Редактор показывает реальные стороны замкнутого помещения. Нажатие на стену
выбирает её внутреннюю поверхность. Для выбранной стены можно установить
высоту облицовки (0 м = только покраска, полная высота = только плитка,
промежуточное значение = плитка снизу и окраска сверху).
Ползунок обеспечивает быстрый выбор, а кнопка **«Точная высота»**
разрешает ввести значение в миллиметрах, например 1350 мм.

Таблица под планом показывает отдельно плитку и покраску по каждому
wall ID. Площади вычисляются по **внутреннему контуру стен**, с учётом высоты
стены, дверей и окон. Проёмы вычитаются из соответствующих вертикальных
участков плитки/покраски, а не из обеих площадей одновременно.

Данные сохраняются вместе с проектом как
\`WorkBoard.wallFinishes\`: \`floorId\`, \`roomId\`, \`wallId\`,
\`tileHeightMm\`. Стены, разделяющие две комнаты, можно отделывать по-разному
с каждой стороны. Прежние проекты без таких записей сохраняют настройки
стен из \`RoomMaterialSettings\`.

После явного назначения поверхностей автогенератор создаёт отдельные
объёмы \`wall_tile\` и \`wall_paint\`, даже если обе отделки встречаются
в одном помещении. Новые задачи содержат \`surfaceWallIds\`.

При сохранении редактор пересчитывает количество и человеко-часы только
у **ещё не начатых автосозданных отделочных задач**. Уже начатые и принятые
задачи не перезаписываются. Задачи, для которых после смены раскладки
получился нулевой объём, получают флаг **«Проверить объём»**
и очищенную привязку к стенам, но не удаляются автоматически, чтобы
не разрушать зависимости и историю приёмки. Пока объём не подтверждён,
новые выполненные объёмы по такой задаче фиксировать нельзя.

**Текущие ограничения:** пока не сделано нанесение отделки на
фотореалистичные 3D-стены, ручное рисование произвольных полигонов
на полу, смена материалов по высоте несколькими независимыми слоями и
автоматическое закрытие задач с нулевым объёмом.



## Зоны покрытий пола: плитка и ламинат

**Работы → Зоны покрытий пола → Помещение.** В версии +155 добавлен
первый геометрический редактор двух покрытий **внутри одной комнаты**.

- Разделение пола прямой вертикальной или горизонтальной линией по плану.
- Линию можно перемещать касанием схемы или ползунком.
- Сторону, на которую укладывается плитка, можно поменять.
- Плитка и ламинат показываются разными цветами на 2D-плане.
- Сервис `WorkFloorSurfaceService` отсекает каждую половину относительно
  фактического `RoomFace.innerPolygon`, в миллиметрах, и считает площадь
  получившихся областей. Пересечений в итоговом объёме нет.
- Сохраняются `WorkFloorFinishSplit.floorId`, `roomId`, `axis`,
  `cutMm`, `tileBeforeCut`; новая запись не изменяет геометрию комнаты.
- Автогенератор добавляет обе операции `floor_tile` и
  `floor_laminate`, если их площади больше нуля; подложка считается только
  для ламинатной части.
- При ручном создании работ подставляется соответствующая площадь.
- Ранее начатые или принятые работы не пересчитываются; у нетронутых
  автосозданных работ объём и трудозатраты обновляются.
- Старые проекты без этой записи продолжают использовать исходный режим
  напольного покрытия помещения.

**Ограничения этой итерации:** один прямой разделитель на помещение,
только два покрытия; произвольные многоугольные границы и три или более
материалов требуют отдельного редактора. Ведётся учёт площади, а не
выкладка плитки или расчёт раскроя ламелей. Ранее отсутствовавшую работу
после нового назначения материалов нужно дополнительно создать через
«Сформировать работы из планировки».


## Многоугольные зоны пола (новая итерация)

**Работы → Нарисовать зоны пола → Выбор комнаты.**

Теперь можно разместить **несколько отдельных контуров** на плане комнаты,
а не только разделить комнату одной прямой. Пользователь выбирает
«Плитка» или «Ламинат», последовательно ставит точки на плане, завершает
контур, затем добавляет другие зоны. Есть отмена последней точки, сброс
чернового контура и удаление отдельной зоны.

Геометрия хранится в миллиметрах как `WorkFloorFinishZone`
(`id`, `floorId`, `roomId`, `material`, `polygon`).
Исходный `RoomFace.innerPolygon` не меняется. При сохранении
`WorkFloorPolygonService` проверяет, что каждый полигон:

- замкнут не менее чем тремя вершинами и имеет площадь от 0,01 м²;
- не выходит за настоящий внутренний контур комнаты, включая вогнутые участки;
- не самопересекается и не занимает площадь другого нарисованного контура;
- относится к выбранному этажу и помещению.

Алгоритм разбивает вогнутые многоугольники на треугольники и суммирует
их пересечения. Оставшаяся **ненарисованная** площадь использует
основное покрытие из настроек комнаты. Поэтому плитка + ламинат
равны площади комнаты, без двойного учёта. Нарисованные зоны имеют
приоритет над прежней прямой границей; её можно вернуть в старом
редакторе «Зоны покрытий пола».

Общий сервис расчёта площадей используется автогенератором и ручным
созданием работ. У не начатых автоматически созданных задач площадь
может быть обновлена. Уже выполненный/принятый объём не меняется;
при изменении его расчётного объёма нужна повторная проверка перед
разблокировкой созависимых работ.

**Ограничения:** сейчас поддерживаются материалы плитка/ламинат,
контуры рисуются точками. Для завершённых зон доступен режим
**«Править вершины»**: выбрать вершину на плане, перетащить с шагом
10/50/100 мм или ввести координаты X/Y с точностью до миллиметра.
Любая правка предварительно проходит те же проверки на пересечения,
попадание в помещение и минимальную площадь, что создание новой зоны.
Пока окно не сохранено, исходные данные проекта не меняются.
Можно сменить материал готовой зоны (плитка/ламинат) без повторного обвода.

**Ещё не сделано:** привязки к углам, осям и соседним границам,
перемещение сразу всего полигона, несколько типов покрытий сверх плитки
и ламината, синхронизация отделочных зон с реальным 2D/3D-материалом
вьюпорта. Тесты геометрии и редактора проходят в CI; требуется
дополнительная проверка на реальном телефоне.


## Навигация по работам в едином «Замере»

Верхняя лента рабочего места теперь содержит пять основных режимов:
**План · Пол · Объекты · Электрика · Работы**.
Эти режимы не заменяют нижнюю системную навигацию
«Главная / Замер / 3D / Развёртки / Профиль».

«Инженерия» и «Материалы» остались доступными в списке инструментов
проектного режима; прежние инструменты и данные не удалены.
В этом списке больше не дублируются пять основных режимов. Режим
«Работы» открывается **в этом же рабочем пространстве** без нового
полноэкранного перехода и без второй верхней панели.

В самом разделе вместо длинной страницы из справочных карточек
показаны три представления:

- **Этапы:** строительные группы в технологически понятном порядке,
  количество принятых работ и краткие статусы. Одновременно раскрыта только одна группа; внутри учитываются
  обязательные предшественники. Независимые работы упорядочены по
  началу и названию, параллельные работы не превращаются в последовательные.
- **График:** переключение «Неделя / Месяц / Гант» на том же экране,
  с прежними данными календаря и связями.
- **Контроль:** прежде всего работы, требующие проверки или приёмки,
  и замечания. План помещений и нагрузка бригад разворачиваются
  по желанию, а не занимают экран постоянно.

Одна кнопка **«+»** добавляет работу (в «Контроле» — запись).
Одно меню **«⋮»** открывает редкие действия: автосоздание работ,
отделку стен, зоны пола, прямое разделение пола, рабочий календарь
и нагрузку бригад. Эти инструменты больше не занимают место на
стартовом экране. Сохраняются все 245 операций, исходные коды, статусы,
проверки объёмов и правила созависимых этапов.

При переключении обратно на план существующие объекты и геометрия
не пересоздаются. Возвращение в «Работы» не добавляет новых задач
самостоятельно.

## Созависимые (параллельные) этапы

Теперь связь работ может быть двух принципиально разных типов:

1. **Обязательный предшественник**: следующая работа начинается только после
   завершения и приёмки предыдущей; планировщик учитывает его дату окончания.
2. **Созависимые параллельные этапы**: две или более операции одной комнаты
   могут выполняться одновременно, но следующий этап, который зависит хотя
   бы от одной из них, сможет начаться **только после приёмки всей группы**.

Пример: черновой электромонтаж, черновая сантехника и вентиляция. Все три
работы выполняются параллельно после подготовки конструктива. Финишная
отделка стен и последующие этапы должны дождаться приёмки всех трёх.
Привязка к группе **не** заставляет одну инженерную работу ждать другую.

**Управление:** `Работы → Карточка работы → Созависимые этапы` либо
при создании новой работы в поле «Созависимые этапы». Можно выбрать несколько
работ того же помещения. Перед сохранением сервис отвергает:
- связь работы с самой собой;
- попытку связать разные помещения/этажи;
- группу, внутри которой уже существует последовательная зависимость;
- связь, из-за которой появились бы недопустимые переносы начатых работ.

При добавлении связи планировщик пересчитывает зависимые сроки по самому
позднему окончанию из всех связанных этапов. При переносе любой работы
группы применяется тот же барьер. Приёмка отдельных работ остаётся
независимой, чтобы не создавать взаимную блокировку.

Автогенератор при включении дополнительных работ связывает между собой
черновую электрику, сантехнику и вентиляцию в пределах одной комнаты.
При повторном создании работы не дублируются, а записи `coStageTaskIds`
сохраняются в JSON проекта. Зависимости не имеют отношения к категориям
поверхностей или физическому объединению помещений.
