# Замер +140 — внутренние размеры помещений

## Требование

По умолчанию подписывать **внутреннюю грань помещения от внутреннего угла до внутреннего угла**. Конструктивная длина стены по оси — самостоятельный параметр модели, не равный обмерному/полезному размеру.

Пример: если по осям между двумя стенами 4000 мм, толщины граничных стен 200 и 200 мм, то внутри помещения между их гранями **3800 мм**. При толщине 200 и 300 мм результат будет **3750 мм**. Размер по оси остаётся 4000 мм и нужен для моделирования/перемещения стены, а не для спецификации внутреннего обмера.

## Геометрия

- Источник измерений — `GeometryService.roomFaces(floor).innerPolygon`: пересечения *смещённых на половину толщины* линий граней реальных стен.
- `RoomInteriorDimensionsService.forFace` объединяет последовательные **коллинеарные** фрагменты одной грани. Это важно после Т-стыка, когда одна длинная стена может состоять из двух или нескольких участков с разными ID.
- Настоящие Г-углы, повороты, ниши и ступеньки от разной толщины сохраняются: не сводим все стены к общей ширине и не выравниваем размеры «на глаз».
- Все расчёты хранят точные `double` в миллиметрах; округление до целого миллиметра происходит **только при показе подписи** на плане.
- Длина `PlanWall` в модели по-прежнему осевая. Мы не заменяем эти значения внутренними, чтобы не сломать привязки, соседние помещения, проёмы, электроточки и 3D.

## Отображение

- В `План → Слои` включено по умолчанию: **«Размеры внутри помещений»**. Размерные линии рисуются чуть внутри соответствующих граней, но отмеряют расстояние точно между внутренними углами.
- Опционально: **«Конструктивные размеры по осям»**. По умолчанию выключено, чтобы не смешивать измерения и не захламлять маленький экран.
- Карточка выбранной стены подписывает собственный параметр как **«Длина по оси»**.
- Небольшие линии по-прежнему учитываются в расчётах даже если не все подписи можно удобно разместить при выбранном масштабе.

## Ручной контроль

- Инструмент **«Размеры»** по умолчанию предлагает касанием указать два внутренних угла замкнутого помещения.
- Система ловит только настоящие углы, а не технические узлы посередине прямой стены от Т-стыков.
- `ControlMeasure` сохраняет точные координаты обоих внутренних углов, исходные IDs конструктивных узлов, и обмер в мм.
- Для инженерных контролей оставлена настройка **«Оси»**. Старые измерения без внутренних координат читаются без миграции.
- В `MeasurementReviewService` внутренний контроль сверяется с текущим **внутренним контуром**, а не с центрами стен. Изменение толщины стены даёт осмысленное расхождение, а не изначально ложные +100/+200 мм.

## Ограничения

- Пока это расстояние между **гранями тел стен**, с учётом их реальных толщин в CAD. Слои будущей штукатурки, плитки и панелей нужно отдельно параметризовать и учитывать в расчёте чистового размера: если слой не внесён в геометрию, мы не можем честно называть вычисленный размер окончательным после отделки.
- Для комнат с криволинейными стенами расчёт отдельных прямых хорд намеренно не показывается как точная внутренняя длина. Следующий шаг — длина дуги по внутренней поверхности и корректная разметка переходных касательных углов.
- Подтверждение точности проекта на реальном объекте требует измерений и источника размеров; автоматический CAD-расчёт не заменяет замер.

## Условия выпуска

- Unit-тесты прямоугольных комнат с разной толщиной стен, L-геометрии и непрерывного размера при Т-разделении длинной стены.
- JSON round-trip внутренних контрольных измерений, сравнение с текущими углами без ложной осевой разницы.
- Полный `flutter analyze`, тесты, релизный APK и ручное тестирование на TECNO. До их прохождения не объявлять функциональность стабильной.
