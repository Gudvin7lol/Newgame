# UI KIT 02 — CAD / ЗАМЕР

Этот документ фиксирует обязательный production-референс экрана «Замер» по утверждённому master-concept и UI KIT 02.

## Приоритет источников
1. Master-concept экрана «Замер» пользователя.
2. UI KIT 02 — CAD / ЗАМЕР: toolbar, snap, nodes, walls, openings, dimensions, source badges, validation, grid/scale, view controls.
3. Общая дизайн-система UI KIT 01.

При конфликте визуального решения экран «Замер» следует этому документу.

## Компоновка mobile
- План — главный объект экрана и занимает максимум доступной площади.
- Слева — узкий вертикальный toolbar: Стены, Проёмы, Объекты, Размеры, Текст, Слои, Проверка.
- Справа — компактные view/CAD actions: фокус, размеры, привязки, геометрия, проверка.
- Внизу справа — миникарта и zoom controls.
- Внизу слева — текущий масштаб.
- Нижняя панель не должна перекрывать центр плана. Авто-fit обязан учитывать зарезервированную высоту инспектора.

## Выбранная стена
При выборе стены показывается компактный inspector, а не универсальная большая форма:
- preview стены;
- идентификатор стены;
- длина;
- угол;
- толщина;
- высота;
- tap открывает точные свойства.

Под inspector идёт quick toolbar:
Стена / Проём / Размер / Текст / Объект / Слой / Удалить.

Ниже — горизонтальный материал strip. На текущем этапе он связан с WallMaterial и обязан менять реальную модель стены.

## Стены
- Состояния: default, selected, demolition/error, proposed.
- Угол построения: 90°, 45°, свободный.
- Привязка включается/выключается отдельно.
- Радиусы и узлы открываются через production geometry tools.
- Толщина не должна ломать layout и переносить название стены по одной букве.

## Узлы и привязки
Обязательные состояния для развития painter:
- default;
- hover/selected;
- snap;
- locked/error.

Типы привязок из UI KIT 02:
- endpoint;
- midpoint;
- intersection;
- perpendicular;
- parallel;
- extension/grid.

## Размеры
- линейный;
- цепочка;
- от проёма;
- вертикальный;
- диагональ.

Источник размера является данными, а не декором:
- Ручной;
- Лазер;
- БТИ / План;
- Расчётный.

Созданный ControlMeasure обязан создавать DimensionRecord с выбранным source.

## Проёмы
Двери/окна должны хранить и редактировать:
- ширину;
- высоту;
- отступ от угла;
- подоконник для окна;
- тип.

## Валидация
Кнопка «Проверка» должна вести в реальный Measurement Review. Ошибки в дальнейшем визуализируются на плане и должны поддерживать переход к проблемному месту.

## Запрещённый drift
- огромная нижняя панель, закрывающая план;
- вертикальный перенос слова «Стена»;
- одинаковые большие floating-кнопки справа без CAD-контекста;
- миниатюрный план по центру пустого viewport;
- фиктивные source badges или материалы, которые не меняют данные;
- замена рабочего редактора статичным mockup.

## Реализация
Reference → tokens/components → real model action → contract test → CI → device check.
