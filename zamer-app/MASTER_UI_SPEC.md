# ZAMER — MASTER UI SPEC

Статус: **обязательный визуальный эталон для реализации**.

Этот документ фиксирует правила переноса утверждённого концепта «Замера» в рабочее Flutter-приложение. Новые экраны и компоненты не должны вводить собственную локальную визуальную систему.

## 1. Пять мастер-экранов

Основная структура приложения:

1. **Главная**
2. **Замер / 2D**
3. **3D**
4. **Оснащение**
5. **Развёртки**

Порядок и названия разделов одинаковы во всей нижней навигации.

Главная находится на верхнем уровне приложения. Четыре рабочих раздела открываются внутри выбранного проекта/этажа, но нижняя навигация остаётся визуально единой.

## 2. Визуальный характер

Интерфейс — профессиональный мобильный CAD/обмерный инструмент, а не стандартное Material-приложение.

Требования:

- тёмная нейтральная база;
- тёплый бежевый главный акцент;
- тонкие контуры панелей;
- компактные профессиональные панели;
- высокая читаемость размеров и чертежей;
- минимум декоративного шума;
- рабочая область всегда визуально важнее навигации;
- никакого случайного cyan/neon редизайна;
- никаких Emoji вместо иконок;
- никаких нестилизованных `AlertDialog`, `Card`, `NavigationBar` или других Material-компонентов в финальном интерфейсе.

## 3. Design tokens

Единственный источник цветов, размеров и типографики:

- `lib/design_system/zamer_tokens.dart`
- `lib/design_system/zamer_theme.dart`

Базовые цвета:

- background: `#0F1419`
- surface: `#1A222B`
- card / surface high: `#202A35`
- accent: `#E9C48F`
- success: `#22C55E`
- error: `#EF4444`
- warning: `#F59E0B`
- info: `#3B82F6`

Локальные magic colors допускаются только для предметных данных сцены/материалов и должны быть обоснованы.

## 4. Общие компоненты

Компоненты создаются один раз и переиспользуются:

- карточки;
- панели;
- кнопки;
- поля ввода;
- segmented controls;
- tool buttons;
- bottom sheets;
- dialogs;
- toast/snackbar;
- tooltips;
- размерные labels;
- object/property panels;
- loading / empty / error states.

Базовые shared-компоненты находятся в `lib/design_system/`.

## 5. Нижняя навигация

Всегда пять пунктов:

`Главная | Замер | 3D | Оснащение | Развёртки`

Active state:

- акцентный цвет;
- лёгкая акцентная подложка/контур;
- более жирная подпись.

Inactive state:

- secondary text color;
- без яркой подложки.

Навигация не должна визуально конкурировать с рабочим объектом.

## 6. Главная

Главная переносится **по готовому экрану UI-kit**, а не проектируется заново при реализации.

Обязательная вертикальная композиция:

1. бренд `ЗАМЕР` и компактная кнопка настроек;
2. строка поиска;
3. две основные кнопки в один ряд: `Новый проект` и `Импорт плана`;
4. `Недавние проекты`;
5. `Шаблоны`;
6. единая нижняя навигация.

На основном полотне Главной **не допускаются** дополнительные hero-блоки вроде `Продолжить работу`, большие карточки активного проекта, отдельная сетка из четырёх быстрых действий или иные секции, которых нет в утверждённом UI-kit. Дополнительные операции (`сканирование`, восстановление копии, облако, экспорт и т. п.) открываются через меню, карточку проекта или Bottom Sheet и не меняют композицию мастер-экрана.

Карточка проекта:

- компактный preview слева;
- название;
- адрес/дата;
- площадь;
- число фото/помещений;
- меню действий;
- высота карточки и плотность должны оставаться близкими к UI-kit, без превращения карточки в hero-баннер.

Главная должна оставаться визуально компактной: типографика, высота поиска, две верхние action-кнопки, список проектов и шаблоны должны помещаться на типичном смартфоне в той же иерархии, что в утверждённом мастер-экране.

Пустое состояние и ошибки используют общую дизайн-систему и не должны раздувать страницу сильнее обычного списка проектов.

## 7. Замер / 2D

Главный приоритет — максимум пространства чертежу.

Обязательные состояния:

- existing wall;
- new wall;
- demolition;
- selected;
- editing;
- conflict/error;
- locked.

Инструменты:

- выбор;
- стена;
- перегородка;
- дверь;
- окно;
- размер;
- объект;
- электрика;
- инженерия.

Размеры должны включать:

- длину стены;
- угол → дверь/окно;
- ширину проёма;
- проём → второй угол;
- диагонали;
- высоты;
- источник размера.

Расчётные размеры визуально отличаются от ручных/фактических.

## 8. 3D

UI — продолжение 2D, а не отдельное приложение.

Режимы:

- Orbit;
- Walk;
- Pan/overview;
- Top;
- Section;
- Hide wall;
- Materials;
- Lighting;
- Render.

Качество:

- Performance;
- Quality;
- Photo.

Photo должен поддерживать настоящий 4K `3840×2160`, а не апскейл размытого кадра.

## 9. Оснащение

Каталог включает:

- поиск;
- категории;
- фильтры;
- сетку объектов;
- избранное;
- карточку/preview;
- параметры;
- добавление в проект.

Категории минимум:

- мягкая мебель;
- столы/стулья;
- корпусная мебель;
- кровати;
- кухня;
- сантехника;
- бытовая техника;
- двери/окна;
- освещение;
- декор/растения;
- строительные элементы;
- другое.

Превью всех моделей должны иметь согласованные камеру, фон и освещение.

## 10. Развёртки

Развёртка занимает основную часть экрана.

Обязательные элементы:

- выбор стены;
- mini plan с направлением взгляда;
- размеры;
- отделка;
- электрика;
- сантехника;
- мебель;
- инженерия;
- заметки;
- переключаемые слои.

Размеры раскладываются по уровням, чтобы подписи не пересекались.

## 11. Состояния

Каждый интерактивный компонент должен иметь необходимые состояния:

- default;
- pressed;
- focused/hovered;
- active;
- selected;
- disabled;
- error.

Обязательные системные экраны:

- loading;
- skeleton;
- empty;
- offline;
- recover;
- sync conflict;
- load/render/export error.

## 12. 2D / 3D / развёртки — единые объекты

Один объект модели данных используется во всех представлениях.

Например, одно окно должно иметь один ID и отображаться в:

- 2D;
- 3D;
- развёртке;
- PDF.

Нельзя создавать независимые копии одного объекта для каждого режима.

## 13. Адаптивность

Приоритет:

1. смартфон portrait;
2. большой смартфон;
3. landscape;
4. планшет.

Минимальная touch area: `44×44`, предпочтительно `48×48`.

Safe Area обязательна.

## 14. Анимации и haptic

Анимации короткие и функциональные:

- button press: 80–120 ms;
- selection: 120–180 ms;
- panel: 180–250 ms;
- page transition: 200–300 ms.

Haptic используется для snap, фиксации объектов и важных подтверждений.

## 15. Порядок реализации

1. Design tokens / theme.
2. Shared components.
3. Единая навигация.
4. Главная.
5. Замер / 2D.
6. 3D.
7. Оснащение.
8. Развёртки.
9. Loading / empty / error / modal states.
10. Адаптивность, анимации, финальный polish.

## 16. Критерий готовности экрана

Экран считается визуально готовым только если:

- соответствует утверждённому концепту;
- использует shared design system;
- не содержит случайных Material defaults;
- нет временных иконок/emoji;
- соблюдены spacing/radius/touch targets;
- все состояния предусмотрены;
- текст и размеры не пересекаются;
- интерфейс работает на нескольких размерах экрана;
- функциональность старой версии не потеряна при визуальном переносе.

## 17. Главное правило

`Concept → Design Tokens → Shared Components → Master Screens → Application`

Не создавать новый визуальный стиль при реализации каждой следующей функции.
